# Задачі для Claude Code

Мета: перетворити папку розширення на нормальний репозиторій з релізами, увімкнути перевірку
оновлень і підготувати публікацію в Chrome Web Store. Контекст коду — у [`../CLAUDE.md`](../CLAUDE.md).

> **Стан (2026-10-02):** задачі 1–4 виконано — репо `ulquorium/youtube-subs-first` (публічне, MIT),
> `UPDATE_URL` прописано, `scripts/release.mjs` і `.github/workflows/release.yml` працюють, реліз v1.10.0 опубліковано.
> Перевірка паритету `_locales` і мов `changelog.json` уже вбудована в `release.mjs` (задача 6 — без словників `content.js`).
> Лишилось: 5 (Web Store), решта 6.

Робимо по порядку. Після кожної задачі — короткий звіт користувачу. Дії, які щось публікують
або щось коштують (створення публічного репозиторію, реліз, відправка в Web Store), — **лише після
явного «так» від користувача**.

## Що спитати в користувача перед стартом

1. GitHub-акаунт/організація і назва репозиторію (пропозиція: `youtube-subs-first`).
2. Репозиторій **публічний**? Перевірка оновлень читає `version.json` без авторизації — для приватного
   репо треба інший хостинг (GitHub Pages з окремого публічного репо, Gist, свій домен).
3. Ліцензія (пропозиція: MIT) і ім'я автора для `LICENSE`.
4. Чи публікувати в Chrome Web Store зараз чи лише готувати матеріали.

## 1. Репозиторій

- `git init`, гілка `main`, `.gitignore` (`*.zip`, `dist/`, `.DS_Store`, `node_modules/`).
- Створити репозиторій через GitHub-конектор (або `gh repo create`), запушити.
- Додати `README.md` для людей: що робить розширення (3–5 пунктів), скріншот-плейсхолдер,
  встановлення з релізу (розпакувати → `chrome://extensions` → Режим розробника → «Завантажити розпаковане»),
  як оновлюватись, посилання на `PRIVACY.md`. Українською + англійська секція.
- `LICENSE`.

**Готово, коли:** репо існує, `main` містить усі файли розширення, README відкривається на GitHub.

## 2. Увімкнути перевірку оновлень

- У корені репо створити `version.json` за зразком `version.example.json`
  (поточна версія з `manifest.json`, `url` → `https://github.com/<owner>/<repo>/releases/latest`,
  `notes` трьома мовами).
- У `background.js` прописати
  `UPDATE_URL = 'https://raw.githubusercontent.com/<owner>/<repo>/main/version.json'`.
- `version.example.json` можна видалити або залишити як документацію.

**Готово, коли:** у popup з'являється «Перевірено: …», при штучно підвищеній версії у `version.json`
на іконці стрілка ↑ і є сповіщення (перевірити й повернути назад).

> `raw.githubusercontent.com` кешує файли до ~5 хв — це нормально для перевірки раз на 6 год.

## 3. Скрипт релізу

Додати `scripts/release.mjs` (Node 18+, без залежностей), запуск `node scripts/release.mjs 2.0.0`:

1. Перевіряє, що робоче дерево чисте і ми на `main`.
2. Перевіряє формат версії і що вона більша за поточну.
3. Оновлює `version` у `manifest.json`.
4. Перевіряє, що в `changelog.json` **першим** записом іде ця версія з `uk`/`en`/`ru` — інакше зупиняється
   з підказкою (тексти пише людина або Claude разом із нею, не генерувати мовчки).
5. Оновлює `version.json` (`version`, `notes` — з першого запису changelog, пункти через `\n`).
6. `node --check` для всіх `.js`, перевірка паритету ключів локалізації (задача 6).
7. Збирає `dist/youtube-subs-first-<версія>.zip` **лише з файлів розширення**
   (manifest, js, css, html, `_locales/`, `icons/`, `changelog.json`) — без `docs/`, `scripts/`, `.github/`,
   `README`, `version*.json`.
8. Комітить «Release v<версія>», ставить тег `v<версія>`.

Пуш тегу і створення релізу — окремо, після підтвердження користувача.

**Готово, коли:** `node scripts/release.mjs <версія>` на чистому дереві дає zip у `dist/`,
що встановлюється в Chrome як розпаковане розширення.

## 4. GitHub Actions: реліз за тегом

`.github/workflows/release.yml`: на push тегу `v*` —
`node --check` усіх js → збірка zip (той самий набір файлів, краще викликати спільну функцію/скрипт збірки)
→ GitHub Release з назвою `v<версія>`, тілом з першого запису `changelog.json` (uk + en) і zip у вкладенні.

Порядок для користувача після цього: `node scripts/release.mjs X.Y.Z` → `git push --follow-tags` → Action
публікує реліз → `version.json` у `main` уже новий → у всіх користувачів сповіщення протягом ~6 год.

> Важливо: `version.json` з новою версією не повинен потрапити в `main` раніше, ніж з'явиться реліз,
> інакше сповіщення поведе на старий реліз. Скрипт комітить усе разом, а тег пушиться одночасно —
> ок. Якщо Action впав — відкотити `version.json`.

## 5. Підготовка до Chrome Web Store

Нічого не відправляти без підтвердження. Підготувати в `store/`:

- `PRIVACY.md` (+ посилання з README): розширення не збирає й не передає дані; працює лише на youtube.com;
  запити йдуть тільки на YouTube від імені користувача (для керування його плейлистами) і на GitHub
  за `version.json`; налаштування зберігаються локально (`localStorage` youtube.com, `chrome.storage.local`).
- `listing.uk.md`, `listing.en.md`, `listing.ru.md`: короткий опис (≤132 символи), повний опис, список функцій.
- Обґрунтування дозволів (для форми Web Store): `alarms` — періодична перевірка оновлень;
  `notifications` — сповіщення про нову версію; `storage` — стан перевірки/бейджа;
  доступ до `https://www.youtube.com/*` через content scripts — сама суть розширення.
  Single purpose: «Налаштування інтерфейсу YouTube під підписки та власні списки».
- Перелік потрібних скріншотів (1280×800): сайдбар, вікно «Зберегти в…», дошка, popup.
  Скріншоти робить користувач — дати йому список.
- Якщо публікуємо в Web Store: оновлення далі йдуть через магазин, тому `UPDATE_URL` для магазинної
  збірки краще вимкнути (окремий прапорець у скрипті збірки, наприклад `--store`), щоб не дублювати сповіщення.

Ризики, які варто проговорити з користувачем: розширення використовує внутрішній API YouTube
(`/youtubei/v1`) з авторизацією через cookie користувача — так роблять багато розширень у магазині,
але рецензія може попросити пояснень. Віддаленого коду немає — це головна вимога, і вона виконана.

## 6. Дрібні технічні покращення (за бажанням користувача)

- **Перевірка локалізації** `scripts/check-i18n.mjs`: паритет ключів `UK`/`EN`/`ru` у `content.js`,
  ключів `_locales/*/messages.json`, мов у кожному записі `changelog.json`. Викликається з release-скрипта і CI.
- **Синхронізація налаштувань між пристроями:** `prefs` зараз у `localStorage` youtube.com (MAIN world
  не має `chrome.storage`). Варіант: додати контент-скрипт в ISOLATED world як міст
  (`window.postMessage` ↔ `chrome.storage.sync`). Обережно з лімітами `storage.sync` (8 КБ на ключ).
- **Перестановка відео на сторінці списку** (`/playlist`), а не лише на дошці — рідна сторінка має свої
  ручки перетягування, перевірити, чи вони працюють, перш ніж щось додавати.

## Чого не робити

- Не додавати збирачі/фреймворки (webpack, React тощо) — проєкт свідомо без збірки.
- Не переносити контент-скрипти в ISOLATED world цілком — зламається доступ до `ytcfg` і Polymer-даних.
- Не міняти ключі `localStorage` (`ysf-prefs-v1`, `ysf-playlists-v2`) без міграції — користувачі втратять порядок.
- Не публікувати релізи й не відправляти в Web Store без явного підтвердження.
